## 0. Выводы одним экраном

1. **Шаг «Всё равно открыть» убирается только платным аккаунтом.** Ни самоподписанный
   сертификат, ни Homebrew, ни Sparkle его не снимают [источник: Apple Support 102445;
   Apple Developer News 06.08.2024]. Это единственная операция, которую без $99 нельзя
   убрать вообще.
2. **Разрешения теряются при каждом обновлении из-за ad-hoc подписи** — это проверено на
   нашем же приложении: `codesign -d` показывает `Signature=adhoc`, `designated => cdhash H"f07c…"`
   (то есть требование привязано к хешу конкретной сборки) [источник: вывод `codesign` на
   /Applications/VoicePaste.app 0.1.15; Apple DTS, forums/thread/795739]. Лечится постоянным
   сертификатом, в том числе самоподписанным [вывод; на двух сборках подряд не проверено].
3. **Минимум разрешений уже достигнут наполовину:** горячая клавиша на `RegisterEventHotKey`
   не требует никакого разрешения [источник: код `HotkeyManager.swift`; Apple DTS в
   forums/thread/820594 перечисляет только PostEvent/ListenEvent/Accessibility, Carbon-клавиша
   в этот список не входит] — тап `CGEventTap` и Input Monitoring не нужны. Остаётся
   микрофон (неизбежно) и «Универсальный доступ» ради вставки ⌘V. Его можно сделать
   **необязательным**: приложение уже умеет класть текст в буфер, но `ReadinessCoordinator`
   не пускает в `ready` без него [источник: код] — это самая дешёвая правка в разделе 5.
4. **Компиляцию Core ML (45–70 с) нельзя ни вшить, ни ускорить, ни отложить навсегда**:
   специализация привязана к чипу и ОС, кэш ведёт система, он сбрасывается после обновления
   ОС и при долгом неиспользовании, и программного способа узнать, попал ли ты в кэш, нет
   [источник: комментарий Argmax в `WhisperKitConfig.prewarm`, Configurations.swift:48–74].
   Можно только **сделать её невидимой**: запускать в онбординге, пока человек занят
   разрешениями, и один раз после смены сборки ОС.
5. **Доставка модели:** вшивать 626 МБ в .dmg не нужно (и вредно для обновлений); нужен
   один автоматический путь «GitHub → зеркало → …» без выбора источника, старт загрузки
   в первую секунду первого запуска и SHA-256, вшитый в приложение. Сейчас хеша нет вообще
   (в `docs/status.md` записано как открытый дефект с 20.09).
6. **$99 стоят ли?** Если цель — «любой Мак, минимум операций», то да: это единственное, что
   убирает барьер на самом входе и открывает основной Homebrew Cask. Но: (а) процесс
   зачисления и оплата у владельца не проверены — для плательщиков из РФ и с картами не из
   их страны на форуме Apple куча жалоб [источник: forums/thread/813530, 826740, 840481];
   (б) единственная команда `S7LYH2FMTA` в проектах Depo — аккаунт Игоря Якубова (EFT),
   не владельца [источник: память eft-v2-ios-release-prep]; подписывать чужим именем
   публичный MIT-проект — решение владельца, не техническое.
   Без $99 разумный потолок — «ad-hoc → свой постоянный сертификат + Sparkle».

## 1. Дистрибуция: что видит пользователь и что делают другие

### 1.1 Gatekeeper на macOS 15 / 26 / 27

- Apple: «В macOS Sequoia пользователи больше не смогут обойти Gatekeeper правым кликом
  (Control-click) для ПО, которое неверно подписано или не нотаризовано. Им придётся зайти в
  Системные настройки > Конфиденциальность и безопасность» [источник: Apple Developer News,
  06.08.2024, developer.apple.com/news/?id=saqachfa].
- Путь обхода: попробовать открыть → Системные настройки → Конфиденциальность и безопасность →
  внизу «Всё равно открыть» (Open Anyway) → подтвердить → ещё раз «Открыть»; приложение
  запоминается как исключение [источник: Apple Support 102445]. Admin-пароль/Touch ID
  требуется [источник: AppleInsider «What's changed in runtime protection for macOS Sequoia»;
  второй независимый источник — TrozWare, troz.net/post/2024/sequoia_app_permissions/].
- Apple Support 102445 прямо говорит: «По умолчанию macOS Catalina и новее также требует
  нотаризации ПО» [источник].
- **README проекта до сих пор советует «правый клик → Открыть»** (раздел «Установка», п. 3,
  «либо: …»). На Sequoia+ этот путь не работает. Строку надо убрать [источник: README.md и
  Apple Developer News выше]. Навык `macos-release` уже написан правильно.
- Про macOS 26 и 27 отдельных изменений Gatekeeper в первичных источниках **не найдено**.
  Сторонние блоги пишут, что «в 26.2+ жёстче» — без ссылок на заметки Apple [не проверено].
  Эта Mac владельца на macOS 27 (Darwin 27.0.0): проверка на ней — один прогон скачанного
  с релиза .dmg в чистой учётной записи [не проверено].
- Утверждение «кнопка «Всё равно открыть» пропадает через час» — один сторонний блог [не проверено].

### 1.2 Homebrew Cask

- Homebrew 5.0.0: флаги `--quarantine/--no-quarantine` объявлены устаревшими, потому что
  «Homebrew не хочет легко предоставлять обход функций безопасности macOS»; «Casks without
  codesigning are deprecated»; Homebrew «will disable all Homebrew/homebrew-cask casks that
  fail Gatekeeper checks in September 2026» [источник: brew.sh/2025/11/12/homebrew-5.0.0/].
- Правила приёма в официальный cask: приложение должно проходить проверку Gatekeeper, не
  требовать её отключения; известность — по метрикам репозитория (порог не нашёл на странице)
  [источник: docs.brew.sh/Acceptable-Casks, Cask-Cookbook].
- Предупреждения вида «cask deprecated … will be disabled on 2026-09-01» видны в issues
  других проектов (CopyQ, PowerShell) [источник: GitHub issues через поиск]. Что реально
  отключено после 01.09.2026 — **не проверено** (результаты поиска все старше даты).
- [вывод] Для нас: в официальный `homebrew/homebrew-cask` ad-hoc приложение не попадёт.
  Свой tap (`brew install --cask ilyaVasiliev1/voicepaste/voicepaste`) возможен, но
  quarantine выставляется как и у .dmg, то есть Gatekeeper-шаг остаётся, а удобство —
  только в одной команде. Сам cask — 20 строк (см. Handy/VoiceInk ниже).

### 1.3 Developer ID + нотаризация

- Цена: 99 USD в год (в местной валюте, где доступно) [источник: developer.apple.com/programs/,
  developer.apple.com/help/account/membership/program-enrollment/].
- Требования нотаризации: подпись `Developer ID Application`, hardened runtime, защищённая
  отметка времени [источник: справочник навыка `signing-and-notarization.md`, сверен
  28.09.2026 по документации Apple; страница документации Apple сейчас рендерится
  скриптом и не читается через fetch — отдельного второго источника не получено].
  Apple: «службы нотаризации автоматически проверяет ваше ПО, подписанное Developer ID»
  [источник: Developer News 06.08.2024].
- **Открытое приложение нотаризовать можно, лицензия значения не имеет.** Это делают Handy
  (MIT), Hex (MIT), VoiceInk (GPL-3.0) [источник: их репозитории — ниже].
- Автоматизация в GitHub Actions: два рабочих образца в клонах.
  - Handy: сертификат .p12 в base64 в секрет, `security create-keychain/import`,
    `tauri-action` с `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`, `APPLE_CERTIFICATE`
    [источник: Handy/.github/workflows/build.yml:222–233, 515–526].
  - Hex: `docs/release-process.md` — тот же набор секретов (`APPLE_ID`, пароль приложения,
    `TEAM_ID`, `MACOS_CERTIFICATE`).
  - У `notarytool` есть вариант без Apple ID: ключ App Store Connect (`--key`, `--key-id`,
    `--issuer`); нужен командный ключ, личный не годится для Notary API [источник: Apple
    TN3147 через поиск; Electron notarize docs]. Это лучше пароля приложения для CI.
  - Репозиторий публичный: стандартные раннеры GitHub бесплатны в публичных репозиториях
    [источник: docs.github.com … about-billing-for-github-actions]. (Про CI GitHub в Depo
    известно, что платные минуты кончились на приватных, здесь не применимо.)
- Что меняется в сборке: hardened runtime + права `com.apple.security.device.audio-input`
  (в `build-release.sh` это уже предусмотрено, «включается только при Developer ID»)
  [источник: CLAUDE.md продукта, строки 107–109]. Нужна проверка, что WhisperKit/Core ML не
  требуют `disable-library-validation` — [не проверено], выяснится первой же нотаризацией.
- Роль в команде: сертификат Developer ID создаётся владельцем аккаунта; может ли это
  сделать Admin — **не проверено**.

### 1.4 Sparkle без Apple-аккаунта

- Подписи обновлений — EdDSA (ed25519): `generate_keys` кладёт приватный ключ в связку
  ключей, публичный идёт в `SUPublicEDKey`; `generate_appcast` подписывает архивы и пишет
  appcast [источник: sparkle-project.org/documentation/]. Apple-аккаунт для подписи
  обновлений не нужен; Developer ID он «рекомендует» и привязывает к нему только ротацию ключей
  и отладочные сценарии [источник: та же страница].
- Код проверки обновления (`SUUpdateValidator.m`): достаточно, чтобы EdDSA-ключи старого и
  нового приложения совпадали и подпись архива была верной; ad-hoc допускается явно
  («If no Apple Code Signing certificate is available, adhoc signing can be used at minimum»);
  запрещено только **снять** подпись, если она была [источник: клон Sparkle,
  Sparkle/SUUpdateValidator.m:255–345].
- Sparkle после загрузки снимает карантин с нового приложения (`SUPlainInstaller.m:48–50`,
  `releaseItemFromQuarantineAtRootURL`) [источник: клон Sparkle] → **обновления через Sparkle
  не вызывают Gatekeeper-диалог снова**.
- [вывод] Подводный камень: при ad-hoc подписи каждое обновление всё равно сбрасывает TCC
  (микрофон + доступ), так что Sparkle без постоянного сертификата даёт «обновилось, и опять
  две системные просьбы». Sparkle осмыслен только вместе с п. 2.3.
- Полный набор: `SUFeedURL` на HTTPS; appcast лежит в публичном репозитории
  (в Китае `raw.githubusercontent.com` может быть медленным — [не проверено]; прибавить
  зеркало или GitHub Pages и тайм-аут).

## 2. Разрешения (TCC)

### 2.1 Что реально нужно

Apple DTS (Quinn) — три разных привилегии, в настройках отображаются неочевидно:

- `PostEvent` (публикация событий: `CGEvent.post`) — и `Accessibility` оба показываются
  в разделе «Универсальный доступ»; `ListenEvent` (мониторинг событий, `CGEventTap`
  listenOnly) — в «Мониторинге ввода»; `PostEvent` и `ListenEvent` совместимы с песочницей,
  `Accessibility` — нет [источник: developer.apple.com/forums/thread/820594, ответ DTS].
- Для `CGEventTap`: `defaultTap` просит «Универсальный доступ», `listenOnly` — «Мониторинг
  ввода»; при наличии «Универсального доступа» мониторинг не просят [источник:
  forums/thread/122492, ответы сообщества; DTS подтверждает разделение в 820594].
- `NSEvent.addGlobalMonitorForEvents` требует именно `Accessibility`, не `ListenEvent`
  [источник: сноска DTS в 820594].

Применительно к VoicePaste:

| Что делаем | Нужно | Источник |
|---|---|---|
| Горячая клавиша | **ничего** (`RegisterEventHotKey`) | код `HotkeyManager.swift:52,125` |
| Запись | микрофон (системный запрос при первой записи) | `AVCaptureDevice.requestAccess` в `ReadinessCoordinator` |
| Вставка ⌘V через `CGEvent.post` | `PostEvent` (раздел «Универсальный доступ») | код `TextInserter.swift:146`: `CGPreflightPostEventAccess() \|\| CGRequestPostEventAccess()` |
| Проверка «готовности» | `AXIsProcessTrustedWithOptions` — это уже **Accessibility**, а не PostEvent | `ReadinessCoordinator.swift:13` |

[вывод] Приложение запрашивает и держит двойное требование: `AXIsProcessTrusted` для
«готовности» и `CGPreflightPostEventAccess` для вставки. Для самой вставки достаточно
одного `PostEvent`. Как именно система сопоставляет тумблер в списке с двумя службами —
на живом Mac не проверено [не проверено]; но у пользователя в любом случае один тумблер.

### 2.2 Есть ли вставка без «Универсального доступа»

Отвечаю по способам:

1. **Буфер без синтетического ⌘V.** Положить текст в `NSPasteboard`, показать HUD
   «⌘V — вставить». Разрешений не требует. Так работает Maccy: без доступа вставка
   «автоматически» не идёт, остаётся ручная [источник: Maccy README, «Why doesn't it paste»].
   Наш код уже кладёт в буфер при отказе [источник: README продукта «Без него текст
   просто копируется в буфер»], но `ready` без доступа не наступает [источник: код].
2. **`CGEvent.post` без доступа** — не работает; системный запрос покажется при первой
   попытке [источник: Apple DTS, forums, «If you try to post a CGEvent, the system will
   present the TCC alert»].
3. **AppleScript / System Events keystroke** — добавляет Автоматизацию и всё равно
   требует доступ для самих нажатий [не проверено; Hex держит AppleScript как резерв:
   `PasteboardClient.swift:88`].
4. **Метод ввода (Input Method Kit)**: приложение регистрируется как раскладка и вставляет
   текст через клиента ввода; Accessibility не нужен, но человек добавляет метод ввода в
   Системные настройки > Клавиатура, и это отдельный бандл [вывод по архитектуре IMK;
   в живую не проверено, и экономии в числе операций нет — только меняется шаг].
5. **Установка текста через AX (`kAXValueAttribute`)** — тот же `Accessibility`.

[вывод] Способа не просить доступ **и** вставлять автоматически нет. Что можно — не требовать
его как условия готовности (п. 1) и просить в момент первой вставки, когда человек
видит, зачем.

### 2.3 Не терять разрешения при обновлениях

- Apple DTS: «macOS отслеживает идентичность кода по **designated requirement**. Ad hoc
  подписанный код не имеет стабильного DR, поэтому macOS не может понять, что версия N+1 —
  тот же код»; «ad hoc подпись отлично подходит для открытых инструментов вроде Homebrew,
  но создаст проблемы для широко распространяемого Mac-приложения»; рекомендуют стабильную
  идентичность, «в идеале выданную Apple» [источник: developer.apple.com/forums/thread/795739].
- Наше приложение: `Signature=adhoc`, `TeamIdentifier=not set`, `designated => cdhash H"…"`
  [источник: `codesign` на /Applications/VoicePaste.app].
- Самоподписанный сертификат даёт стабильное требование «identifier + certificate leaf»
  [вывод]. Один сторонний проект сообщает, что шесть пересборок под постоянным
  сертификатом сохранили разрешение «Универсальный доступ» [источник: shannoncoat,
  git.bdeshi.space — единичный репозиторий, не Apple]. Gatekeeper-шаг при этом остаётся.
- План проверки (вывод): подписать две сборки сертификатом, выдать оба разрешения, заменить
  приложение второй сборкой, убедиться, что запросов нет. Ключ хранится только в связке
  владельца; потеря = сброс разрешений у всех (бэкап .p12). Переход ad-hoc → сертификат
  сбросит разрешения у существующих пользователей один раз.
- Побочный эффект ad-hoc: сброс сам по себе приводит к тому, что в списке «Универсальный
  доступ» остаётся запись, которая визуально включена, но не действует; пользователю
  нужно удалить запись и добавить заново [источник: описание в 795739 и сторонних разборах;
  у нас, по README, это уже встречалось — не проверено в журнале].
- Если запущено из .dmg или «Загрузок»: Gatekeeper может запускать приложение с рандомным
  путём (App Translocation); `SMAppService.mainApp.register()` и TCC от этого страдают
  [не проверено: первичный источник по translocation не получен; поиск вернул только темы
  про `SMAppService`, status 78 и копии приложения в нескольких местах]. Дешёвая мера —
  как делает библиотека LetsMove: при запуске не из `/Applications` предложить переместить.
  Ни VoiceInk, ни Hex, ни Rectangle/Maccy/Ice этого в коде не имеют (поиск по
  `LetsMove|moveToApplications|translocat` — пусто) [источник: клоны].

### 3.2 Три стратегии

| | Вшить в .dmg | Скачать при первом запуске (сейчас) | По требованию |
|---|---|---|---|
| Лимит GitHub: файл < 2 GiB, до 1000 файлов в релизе, суммарного предела нет [источник: docs.github.com about-releases] | 626 МБ влезает, но .dmg станет ~650 МБ | да | да |
| Первое использование | сразу после запуска (компиляция остаётся) | ждать загрузку | ждать при первой диктовке |
| Обновления приложения | либо 650 МБ каждый раз, либо модель внутри .app — менять нельзя без поломки подписи | модель отдельно, приложение 5–10 МБ | то же |
| Китай | один GitHub-файл, обрывы переживаются возобновлением в браузере | наши источники + возобновление | то же |
| Работа | проще всего, но раздувает релиз | сделано, надо добавить хеш и убрать выбор | ещё сложнее UX |

[вывод] Вшивать полную модель не нужно. Единственная осмысленная вшивка — **компактная**
(`base` ~147 МБ), чтобы диктовка работала через секунды после установки, пока основная
скачивается; цена — +147 МБ в каждом обновлении (если без дельт Sparkle) и заметно худшее
качество на русском, то есть плохое первое впечатление. Не рекомендую без данных об отвале
на первом запуске [не проверено].

Как делают другие:
- **Handy**: `.dmg` без модели; каталог моделей с `sha256`, источники — собственный CDN
  `blob.handy.computer` и HF; «sha256 — якорь доверия для загрузки из любого источника (HF или
  зеркала)» [источник: Handy/src-tauri/src/managers/model.rs:45–54, 125–135]. Выгрузка по
  простою, по умолчанию **5 минут** [источник: settings.rs, `Min5 #[default]`].
- **VoiceInk**: модели `ggml-*.bin` с `huggingface.co/ggerganov/whisper.cpp`, без зеркала;
  в онбординге экран «model» [источник: TranscriptionModel.swift:242; Onboarding/State].
  Шагов онбординга — 8 (`permissions, microphone, model, api, experience, contextAwareness,
  trust, license`) — это пример того, чего не надо повторять.
- **Hex**: через WhisperKit/FluidAudio с HF, `downloadBase: nil` [источник: TranscriptionClient.swift:360].
- **MacWhisper**: данных нет [не проверено].

### 3.3 Целостность

- Сейчас: проверяется только существование ожидаемого файла [источник: код
  `GitHubModelDownloader.swift:207–231`; `docs/status.md:82`]. Приложение не в песочнице.
- Что надо: SHA-256 на каждый архив **вшить в приложение** (константой рядом с URL) и
  считать потоково (`CryptoKit SHA256.update`), пока качается. Подписывать манифест не нужно:
  корень доверия — само подписанное приложение, а значит и сторонние прокси для скачивания
  становятся безопасными. Подписанный манифест (Ed25519, `Curve25519.Signing`) нужен
  только если хеши хотят брать из сети, чтобы выкладывать новые модели без релиза
  приложения [вывод]. Ключ можно взять отдельный от Sparkle.
- Распаковка `ditto -x -k` уже атомарная (staging) — оставить.

## 4. Запуск и фон

### 4.1 Что реально происходит у нас

- Модель держится в памяти по умолчанию: `modelUnloadMinutes` по умолчанию `0` = «никогда»
  (AppSettings.swift:159); выгрузка только по давлению памяти
  (`DispatchSource.makeMemoryPressureSource`, `ModelManager.swift:787`) и по таймеру при
  `unloadMinutes > 0` (`endTask`) [источник: код].
- Прогрев: `prewarm()` вызывается один раз, когда приложение стало `ready`, и ещё раз
  в начале каждой записи [источник: `AppState.swift:268, 367`].
- Кэш специализации лежит у нас: `~/Library/Caches/com.ilyavasiliev.voicepaste/
  com.apple.e5rt.e5bundlecache`, **129 МБ** [источник: `du` на этой машине].
- Простой: приложение 4 суток 3 часа, 0,0 % CPU, RSS 42,7 МБ (модель выгружена),
  8 потоков; в `top` накопленных «idle wakeups» 33 690 → около 0,1 в секунду
  [источник: `top -pid`, `ps` на этой машине; значение колонки IDLEW как накопленное —
  [не проверено]]. Таймеров `Timer`/`scheduledTimer` в коде нет [источник: поиск по
  VoicePaste].

### 4.2 Специализация Core ML и «45–70 с»

- Модели Core ML (`.mlmodelc`) приходят независимыми от устройства; при первой загрузке
  Core ML «специализирует» их под чип; результат — на диске, вне пакета приложения; «кэш
  ведёт Apple, он вычищается **после каждого обновления ОС** и если модели долго не
  использовались; у третьей стороны нет API, чтобы проверить, попадёт ли загрузка в кэш»
  [источник: Argmax WhisperKit, `Configurations.swift:48–74`]. Это второй, независимый от
  нашего измерения, источник той же картины: на `iPhone 18 Pro` холодная загрузка на ANE
  занимает десятки секунд, повторная мгновенна [источник: Apple forums/thread/850058, жалоба
  разработчика; DTS-ответа нет].
- У Argmax специализация `turbo_632MB`: 25,7 с на M2, 149 с на iPhone 16; «626MB» грузится
  быстрее и работает чуть медленнее [источник: issue #221 по сводке в
  `2026-10-14-hallucination-and-speed.md:74`].
- `prewarm: true` в `WhisperKitConfig` — **не ускоряет** компиляцию: загружает и выгружает
  модели по очереди, чтобы снизить пик памяти, и **удваивает** время загрузки при попадании
  в кэш [источник: комментарий там же и `Models.swift:19–25`: `prewarmMode ? nil : loadedModel`].
- `MLModelConfiguration.computeUnits`: `.cpuAndGPU` обходит компиляцию под ANE — разработчик
  в Apple forums использовал её, чтобы избежать зависания, `.all`/`.cpuAndNeuralEngine`
  вставали на `MILCompilerForANE error` [источник: forums/thread/770530, iOS 18.2]. По
  умолчанию WhisperKit: mel — `cpuAndGPU`, энкодер и декодер — `cpuAndNeuralEngine`
  [источник: Models.swift, сводка в `…hallucination-and-speed.md:87`]. Цена GPU по
  скорости/энергии на M-серии в 2026 — не измерена [не проверено].
- Обновление ОС: у владельца macOS 27 (Darwin 27.0.0) — любой следующий минор снова
  сбросит кэш [вывод].

### 4.3 Что с этим можно сделать (конкретные API)

| Цель | Как | Оговорка |
|---|---|---|
| Скрыть компиляцию на первом запуске | запускать `ensureLoaded()` сразу после скачивания, пока человек в экране разрешений; показывать «Подготовка модели» с прогрессом | компиляция не параллелится со скачиванием — это 1–2 минуты ожидания, которые нельзя убрать, пока нет меньшей модели [вывод] |
| Скрыть после обновления ОС | хранить `ProcessInfo.processInfo.operatingSystemVersionString` (с билдом) в `UserDefaults`; при смене — один раз прогреть в фоне при первом запуске, показать в меню «Оптимизация под новую macOS» | точный момент сброса кэша не наблюдаем; снимок по времени загрузки `ensureLoaded` > 10 с как признак холодного кэша [вывод] |
| Прогрев вне пользовательской работы | `NSBackgroundActivityScheduler` (QoS `.utility`, один раз, `tolerance`) — система сама выбирает момент простоя и питания | документированный API Apple для отложенной работы; для Core ML не проверено [не проверено] |
| Не платить 45 с при обычном запуске | не выгружать модель вместо «простоя 5 минут» — ключевое: **выгрузка стоит 1–2 с при тёплом кэше**, а не 45 с; 45 с платятся только при потере кэша | кэш = 129 МБ в `~/Library/Caches`; чистильщики и «Оптимизация хранилища» могут его убрать [вывод; не проверено] |
| Дать быструю диктовку пока кэш холодный | загружать `.cpuAndGPU` для энкодера на время холодного кэша и переключаться | требует замера; может быть медленнее [не проверено] |

### 4.4 Энергия и фон

- `LSUIElement = YES` в Info.plist (есть, `Resources/Info.plist:23`) — приложение без значка
  в Dock; Ice так же [источник: project.pbxproj:321]. На нашем AppDelegate Dock-значок
  управляется отдельно (`applyDockVisibility`) [источник: код].
- App Nap: Apple — приложение «подходит» для App Nap, если не занято работой с пользователем
  и давно не обновляло видимое окно; замедляет CPU и частоту таймеров; рекомендация
  «оставаться в простое как можно дольше, просыпаться только по событиям»
  [источник: Apple «Energy Efficiency Guide for Mac Apps», App Nap и Best Practices —
  developer.apple.com/library/archive/…/power_efficiency_guidelines_osx/]. Источник архивный;
  состояние в macOS 26/27 не перепроверено [не проверено].
- Практика: на время записи и распознавания — `ProcessInfo.processInfo.beginActivity(options:
  [.userInitiated], reason:)` и `endActivity`; вне их — ничего держать не надо [вывод;
  в коде не искал].
- Что реально потребляет в простое: (1) модель в памяти — 0 CPU, но сотни МБ RAM; (2) таймеры
  с коротким периодом — у нас нет; (3) постоянный `AVAudioEngine` / подписка на устройства —
  у нас движок создаётся на сессию (`AudioCaptureService.swift:173, 245`); (4) глобальные
  `CGEventTap` — у нас нет; (5) опрос состояния разрешений — `AppState` подписан на
  `didBecomeActive` (`AppState.swift:204`) без таймера.
- **По бездействию против по давлению:** давление — реактивно и не гарантирует, что память
  освободится до того, как Mac начнёт сжимать/свопить; бездействие предсказуемо. [вывод]
  Handy по умолчанию 5 минут (источник выше). Разумно: таймер простоя 10–15 мин **плюс**
  давление памяти (уже есть); цена возврата 1–2 с при тёплом кэше. Только какая именно
  RAM у загруженной модели на этой Mac — не измерял (модель сейчас не загружена) [не проверено].

## 5. Рекомендация: «скачал → перетащил → нажал → работает»

### 5.1 Как выглядит путь

Сейчас (по README, коду и онбордингу): скачать .dmg → открыть → перетащить → запустить →
блок Gatekeeper → Настройки → «Всё равно открыть» → пароль → запустить → онбординг:
**выбрать источник модели** → ждать 626 МБ → запрос микрофона → открыть «Универсальный доступ»
в Настройках, найти приложение, включить (возможно, перезапуск) → первая диктовка ждёт
компиляцию 45 с.

Идеал при платном Developer ID: скачать → перетащить → двойной клик (один диалог «из
интернета, открыть?») → сразу идёт загрузка модели → системный запрос микрофона (1 клик) →
«нажми ⌥Space» → готово, при первой вставке — ещё один запрос «Универсальный доступ» (1
тумблер) → работает.

Без аккаунта: то же, но с блоком Gatekeeper после п. 3 (три действия: открыть Настройки,
«Всё равно открыть», пароль).

### 5.2 Что можно убрать, что нельзя

| Операция | Убирается? | Чем | Оценка работы* |
|---|---|---|---|
| Gatekeeper-блок | только $99 | Developer ID + нотаризация | 1–1,5 дня + аккаунт |
| Совет «правый клик → Открыть» в README | да | править текст | 0,1 дня |
| Выбор источника модели | да | авто-цепочка + возобновление | 1–1,5 дня |
| Ожидание загрузки до разрешений | да (параллелить) | старт загрузки в первую секунду | входит выше |
| Целостность модели | да (дефект) | SHA-256 в приложении | 0,5 дня |
| Микрофон | нет | системный запрос | — |
| «Универсальный доступ» | можно отложить и сделать необязательным | не блокировать `ready`; вставка → буфер + подсказка | 0,5–1 день |
| Повторные запросы после обновления | да | постоянный сертификат (самоподписанный или Developer ID) | 0,5 дня + проверка на двух сборках |
| «Скачай новый .dmg» | да | Sparkle + EdDSA | 1–1,5 дня |
| Компиляция 45 с при первой диктовке | скрыть, не убрать | прогрев в онбординге; после смены ОС — в фоне | 0,5–1 день |
| Подтверждение «вход при запуске» | нет, система | `SMAppService` показывает своё | — |

\* оценки в днях — **оценка**, не замер; для одного разработчика, с тестами по правилам Depo.

### 5.3 Порядок (если «минимум сложных операций» — главное)

1. Правка README (убрать правый клик), по умолчанию — автозагрузка модели без выбора,
   SHA-256, необязательный доступ. Всё без денег. ~3–4 дня.
2. Постоянный сертификат и **только потом** Sparkle: без сертификата Sparkle умножает
   запросы разрешений. ~2 дня.
3. Решение владельца по Developer ID: если платёж и зачисление проходят, переносим
   подпись и нотаризацию в CI (образцы — Handy, Hex), добавляем cask в свой tap. Тогда
   Gatekeeper-шаг уходит. ~1,5 дня + аккаунт.
4. Не делать без данных: вшитую малую модель, кастомный метод ввода (IMK),
   `cpuAndGPU` на время холодного кэша.
