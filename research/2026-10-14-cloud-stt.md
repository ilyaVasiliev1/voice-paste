# Облачные API распознавания речи как опция для VoicePaste (гибрид «локально по умолчанию, облако по выбору»)

Дата исследования: 14.10.2026. Метки: [источник] — прочитано на официальной/первичной странице; [незав.] — независимый бенчмарк; [вендор] — самоотчёт поставщика; [вывод] — моё заключение; [не проверено] — не нашёл подтверждения или страница не открылась.

Ограничение метода: страницы читались через WebFetch (малая модель делает выжимку), поэтому цифры с цен-страниц — выжимка, а не дословная копия; у многих страниц дата публикации не указана — там, где она есть, указана. Ничего не устанавливалось, аудио не отправлялось, платных запросов не было.

## 0. Главное за минуту

1. Независимых замеров именно «русский + новые облачные модели 2026» почти нет. Лучшие найденные: репозиторий berdachuk/stt-ru-benchmark (06–07.08.2026, три домена, но только GigaAM v3, Deepgram Nova-2/3, Whisper-turbo, Parakeet — без ElevenLabs, OpenAI gpt-*-transcribe, Google, Soniox) и обзор на Хабре от 10.02.2026 (20 YouTube-видео, смешанные языки, эталон — авторские субтитры). Лидерборд Artificial Analysis — только английский (AgentTalk, VoxPopuli, Earnings22 [источник, языки на странице не названы]).
2. Самый сильный результат на русском в независимом тесте показал не облако, а **локальный GigaAM v3** (6.57% на аудиокнигах, 6.95% на спонтанной речи) — лучше Whisper-turbo (9.89% / 7.73%) и Deepgram Nova-3 (8.88% / 7.12%) [незав.]. Это аргумент проверить локальную замену до подключения облака (см. раздел 7).
3. Из-за Китая и VPN главный фильтр — не качество, а допуск: у OpenAI Китай и Гонконг не в списке поддерживаемых стран; у Groq (по ответу на форуме) ограничены «Greater China» и Россия; у ElevenLabs заблокирована Россия, Китай в списке блокировки не найден; Gemini API — Китая нет в списке доступных регионов. Технически через VPN-выход в поддерживаемой стране это работает, но формально — нарушение условий с риском блокировки ключа/аккаунта [вывод].
4. Если добавлять одно облако: **ElevenLabs Scribe v2** (лучшее качество среди проверенных, $0.22/ч, словарь терминов, диаризация, таймкоды) — с оговорками про политику данных и Россию. Второе, если нужна «чистая» политика данных и один код с Groq/своим сервером — **OpenAI gpt-transcribe / gpt-4o-mini-transcribe через OpenAI-совместимый эндпоинт**.

## 3. Латентность и устойчивость к высокому RTT

Что измерено [незав.]:
- AA-WER Streaming (01.06.2026, англ., от конца речи по Silero VAD до первого финального): Deepgram Flux 0.020 с, Nova-3 Realtime 0.06 с, Soniox Realtime 0.06 с, Scribe v2 Realtime 0.14 с (WER 3.64%), AssemblyAI U3 Realtime Pro 0.47 с (первый partial), Voxtral Realtime WER 5.3% финал, OpenAI GPT Realtime Whisper WER 5.1%. Это серверные задержки без сетевого RTT.
- Coval: Nova-3 TTFT 992 мс медиана, Scribe v2 2080 мс (метрика другая, приводит конкурент Gradium) — расхождение с AA не примиряется [незав., вторичный].
- Файловый режим (AA speed factor): Deepgram 626×, Groq turbo 122×, Chirp 3 30×, Scribe v2 69×, gpt-4o-transcribe 36.8×, Soniox async 44×. Для 30 с аудио это 0.05–1 с обработки.

Для 5–30 с клипа за туннелем [вывод]:
- Доминирует сеть: DNS + TCP + TLS 1.3 ≈ 2–3 RTT, загрузка 30 с аудио (≈250–500 КБ в Opus/AAC; 25 МБ — лимит OpenAI/Groq) и ответ. При RTT 300–800 мс накладные расходы 1–3 с независимо от модели; разница между «быстрой» и «медленной» моделью на сервере (0.1 против 0.6 с) окажется в шуме.
- Замеры с ноутбука мерят туннель, а не продукт (13 мс против 790 мс на одном запросе, из CLAUDE.md); числа должны сниматься с named route.
- Потоковый режим: плюс — аудио уходит по мере речи, к концу фразы остаётся 1 RTT + финализация (0.06–0.5 с); минус — долгоживущий WebSocket через VPN чувствителен к потерям и перезапускам туннеля, нужен fallback на файловый режим. Для push-to-talk диктовки 5–30 с начинать стоит с файлового режима: проще, переживает обрывы повтором.
- Сжатие перед отправкой (Opus/AAC 16 кГц моно) сокращает загрузку в 10+ раз против WAV [вывод]; формат должен поддерживаться: OpenAI — mp3, mp4, mpeg, mpga, m4a, wav, webm [источник]; Azure — WAV, MP3, OGG/OPUS, FLAC и др. [источник].
- Региональные эндпоинты: Deepgram — серверы только в США, «ожидайте повышенную латентность из других стран» [источник]; Groq — ЦОДы в США, Канаде, Саудовской Аравии, Финляндии, Австралии [форум]; Chirp 3 — регионы `us`, `eu` GA (asia-* местами Preview) [источник]; Alibaba — Сингапур и Пекин [источник]; Azure China — отдельные регионы .azure.cn только для организаций с присутствием в Китае [источник]. Какой эндпоинт ближе к вашему VPN-выходу, нужно мерить [не проверено].

## 5. Доступность из Китая и через VPN

Что подтверждено [источник]:
- **OpenAI**: страница supported-countries — материковый Китай и Гонконг **не в списке**; «доступ вне перечисленных стран может привести к блокировке/приостановке аккаунта». С 09.07.2024 OpenAI блокирует трафик из неподдерживаемых регионов; платежи из неподдерживаемых регионов тоже могут вызывать блокировку (СМИ 2024) [вторичный]. Россия тоже не в списке.
- **Groq**: на форуме сообщества — «GroqCloud доступен везде, кроме ограниченных регионов: Greater China, Russia, Syria, Iran, North Korea, Cuba» (страница по прямой ссылке не открылась — по snippet; Гонконг в «Greater China» — не подтверждено).
- **ElevenLabs**: блокируются Беларусь, Куба, Иран, Северная Корея, **Россия**, Сирия, части Украины; Китая в списке нет; серверы облака могут быть ошибочно помечены [источник]. Сам API-доступ из Китая отдельно не подтверждён.
- **Gemini API / AI Studio**: Китая, Гонконга, России в списке доступных регионов нет [источник].
- **Azure Speech**: в Китае — отдельный Azure 21Vianet (.azure.cn), нужен бизнес-присутствие в КНР; глобальный Azure из Китая — не проверено.
- **Alibaba Model Studio**: международный регион Сингапур и китайский Пекин — это нативный китайский поставщик, из Китая должен быть доступен; доступность международного аккаунта без китайского ID — не проверено.
- **iFlytek**: международная платформа global.xfyun.cn — отдельные ключи [вторичный, не проверено].
- **Deepgram, AssemblyAI, Soniox, Speechmatics, Gladia, Mistral**: страниц об ограничениях по странам и доступности из КНР я не нашёл [не проверено]. Deepgram — серверы только в США [источник].
- **Yandex SpeechKit, SaluteSpeech**: российские; доступность из Китая и прокси-путь не проверялись; SaluteSpeech требует в экосистеме Сбера российский корневой сертификат (по общеизвестной практике) [не проверено].

Что это означает [вывод]:
1. Технически трафик из Китая через VPN выходит с IP страны выхода; провайдеры, которые фильтруют по IP, видят не Китай. Но условия OpenAI/Groq формально запрещают доступ из неподдерживаемых территорий, а OpenAI целенаправленно ищет такие ключи (форум: сообщения «traffic from unsupported regions»). Риск — отзыв ключа, а не просто «не работает».
2. Оплата — отдельный риск: карты российского и китайского эмитента часто не проходят у западных поставщиков. Для BYO-key это задача пользователя, но продукт должен честно сказать об этом.
3. В продукте: показать, какой регион выхода поддерживается, и не делать «молчаливый» повтор через другого провайдера.
4. Проверка доступности — только руками с вашей машины и вашего маршрута (не делал: отправка запросов запрещена ограничениями задачи).

## 6. Как это делают Wispr Flow, Superwhisper, VoiceInk

| Продукт | Модель облака | Ключ | Приватность (по их страницам) |
|---|---|---|---|
| Wispr Flow | Только облако на их серверах: звук идёт на их инфраструктуру, часть запросов — сторонним моделям по ZDR-договорам; офлайн-режима и BYO-ключа не нашёл [источник: docs.wisprflow.ai; пробел] | нет | «Privacy Mode» = zero data retention, отдельный тумблер Cloud Sync; по умолчанию — расходятся источники (док не указывает; сторонний обзор — «выкл. по умолчанию») |
| Superwhisper | Локально (Whisper Large v3 Turbo, Parakeet Multilanguage, Cohere Transcribe) + облачные модели; **BYO-ключ у Pro-пользователей** (в настройках режима), корпоративные общие ключи; прокси ли — в доке не сказано, на странице моделей говорится о прокси [источник] | да | «Data handling governed by your agreement with that provider»; локальные модели не отправляют ничего; кастомный словарь при облачной голосовой модели уходит вместе с аудио |
| VoiceInk | По умолчанию всё локально; облачные провайдеры (Groq, OpenAI, Deepgram, ElevenLabs, Speechmatics, Soniox, Gemini, Mistral, Anthropic, Cerebras, OpenRouter, Ollama и кастомные OpenAI-совместимые) включаются **только когда пользователь ввёл ключ и выбрал провайдера** | да, **ключ хранится в Keychain**, «never sent to VoiceInk servers»; аудио уходит провайдеру, на серверах VoiceInk не хранится [источник: tryvoiceink.com/privacy] |

Вывод [вывод]: ближайший образец для VoicePaste — модель VoiceInk (локально по умолчанию, облако = ключ + выбор, ключ в Keychain, своих серверов нет). Проксирование через свой сервер даёт простоту пользователю, но делает вас оператором/процессором данных и требует документов, субобработчиков и расходов — для личного продукта нецелесообразно.

## 7. Юридически-практическое: что нужно, чтобы продукт отправлял аудио в сторонний API

Статус: это инженерно-продуктовый разбор, не юридическая консультация; применимость 152-ФЗ, PIPL, GDPR к личному использованию автора и к распространяемому приложению — [не проверено], передать ролям legal-ru / legal-cn при распространении.

1. **Явное согласие и раскрытие, до первой отправки.**
   - Apple Guideline 5.1.2(i) (дословно): «You must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so» [источник: developer.apple.com, прочитано 14.10.2026]. Это обязательно для App Store; для распространения вне магазина формально не действует, но это разумная планка [вывод]. Правило действует с 13.11.2025 [вторичный]; неясно, считается ли «третьей стороной» собственный API пользователя — не уточнено Apple [вторичный].
   - Экран согласия: название провайдера, что отправляется (аудио, словарь терминов, язык), в какую страну/регион, срок хранения у провайдера, ссылка на его политику, кнопка «Использовать облако» (не «Принять»), отключение в один шаг.
2. **Облако выключено по умолчанию**; локальный путь остаётся рабочим при отказе облака; без молчаливого переключения на облако при ошибке локальной модели (приватность — явный выбор).
3. **Ключ пользователя (BYO) в Keychain**: класс `kSecClassGenericPassword`, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (или `AfterFirstUnlock`, если нужны фоновые запросы), не в `UserDefaults`/plist/логах/телеметрии, не отправлять на свои серверы, маскировать в UI, кнопка «удалить ключ» = отключить провайдера. Прецедент — VoiceInk [источник]. Детали Keychain — общеизвестная практика Apple [не проверено в этой сессии].
4. **Транспорт и следы**: только HTTPS (ATS), без логирования содержимого, временные файлы аудио удалять сразу после ответа, не кэшировать, не писать в crash-отчёты; в UI — индикатор «звук уходит провайдеру X». Подключать по возможности режимы провайдера без хранения (OpenAI transcriptions — «None» по умолчанию [источник]; Deepgram — `mip_opt_out=true` в каждом запросе [источник]; ElevenLabs — `enable_logging=false` только для enterprise [источник]; AssemblyAI — TTL и opt-out в Data Controls [источник]).
5. **Договорные отношения**: при BYO-ключе контракт пользователь↔провайдер, а ваше приложение — «клиент»; формулировка Superwhisper — прямой образец [источник]. Условия провайдеров (регионы, запрет прокси-доступа из неподдерживаемых стран, платежи) — ответственность пользователя; приложение обязано честно предупредить, особенно про Китай/Россию (см. раздел 5).
6. **Если когда-нибудь собственный сервер/прокси**: вы становитесь оператором/процессором; нужна политика конфиденциальности, список субобработчиков, трансграничная передача (152-ФЗ — РФ→зарубеж; PIPL — КНР→зарубеж; GDPR при ЕС-пользователях), уведомление регулятора где нужно [не проверено; legal-ru/legal-cn]. Для личного проекта — отказаться.
7. **Чувствительное**: сообщения «людям» содержат персональные данные третьих лиц (имена, контакты); добавить в экран согласия предупреждение «не диктуйте в облако то, что не хотите отправлять поставщику».

## 8. Практические замечания по текущим недостаткам (вне облака)

- «Нет пунктуации» у Whisper large-v3 обычно не свойство модели: Whisper-семейство генерирует пунктуацию; отсутствие чаще следствие настроек декодирования/промпта/постобработки в клиенте [вывод, не проверено на вашем коде]. Стоит проверить `WhisperKit` параметры (без подавления пунктуации, `prompt` с примером пунктуированного текста) до подключения облака.
- Галлюцинации на тишине — известная проблема large-v3 (arXiv 2501.11378; фиксированные фразы на тишине; рекомендуют VAD-предобработку) [вторичный]. Перед отправкой в облако VAD-обрезка тишины даёт и меньше галлюцинаций, и меньше платных секунд (у Groq минимум 10 с на запрос [источник]).
- Локальная альтернатива с лучшим независимым результатом на русском — GigaAM v3 (6.57% / 6.95% против 9.89% / 7.73% у Whisper-turbo) [незав.]; для китайского — SenseVoice/Fun-ASR (открытые модели, вендорские замеры) [вендор]. Что подключить локально, а что — отдельная задача.

## 9. Рекомендация

Если добавлять облако, то минимально:

1. **ElevenLabs Scribe v2** — основное «качественное» облако: лучший показатель AA (2.2%), первое место на Хабре (0.388), словарь терминов до 1000 ($0.05/ч), диаризация до 32, слова с таймкодами, Realtime 0.39 $/ч, цена $0.22/ч. Минусы: политика обучения на данных в найденных документах не оговорена, ZRM только enterprise; Россия заблокирована (если ключ/платёж российский — проблема); Китай явно не подтверждён; китайский — «High accuracy», не «Excellent».
2. **OpenAI gpt-transcribe (или gpt-4o-mini-transcribe $0.18/ч) по OpenAI-совместимому API** — «чистая» политика данных (для транскрипции нет хранения/abuse-логов, не обучается) и тот же код-путь заводит Groq ($0.04/ч), Mistral Voxtral и собственные эндпоинты. Минусы: Китай/Россия не поддерживаются; нет таймкодов у новых моделей (только whisper-1); качество на русском по независимому тесту не измерено.
3. Для китайских лекций отдельным пунктом позже: **Alibaba Fun-ASR (Сингапур)**, $0.126/ч, диалекты, пунктуация+ITN; но качество и правила доступа для международного аккаунта — не проверено. Для дешёвого пакетного режима с хорошей ценой — Soniox (≈$0.10/ч, `ru`/`zh` есть), но нет подтверждённой политики данных.

Не рекомендую для вашего случая: Deepgram (русский не лучше Whisper-turbo в независимом тесте, по умолчанию участвует в обучении, серверы только в США); Yandex SpeechKit (низкий результат в Хабре, российский контур); SaluteSpeech (продажа пакетов физлицам прекращена); Azure/Google Cloud (тяжёлая регистрация, заметно дороже; плюс Google STT по умолчанию не логирует — аргумент только если уже есть GCP-аккаунт).

Порядок работ: (а) сначала проверить локально пунктуацию/VAD/GigaAM v3; (б) одним протоколом `TranscriptionProvider` (локальный, OpenAI-совместимый, ElevenLabs); (в) собственный прогон 20–30 клипов с вашего маршрута (качество, пунктуация, латентность file vs stream); (г) экран согласия и Keychain.
