# Голосовая диктовка и голосовой ввод для агентов: обзор и разрыв с VoicePaste

Дата исследования: 14.10.2026. Метки: [источник] — прочитано в первичном источнике (репозиторий, сайт, документация вендора); [вывод] — моё заключение из прочитанного; [не проверено] — не нашёл подтверждения или нашёл только вторичные/маркетинговые.
Числа GitHub (звёзды, дата push) — из GitHub API на 14.10.2026. Клонировал (`--depth 1`, ничего не запускал): VoiceInk, Handy, OpenWhispr, Hex (старый Swift) и Hex (новый Rust, anomalyco/hex), OpenSuperWhisper, FluidVoice, epicenter (Whispering), TypeWhisper, Muesli, OpenLess, voicemode, voicetypr, amical, Tambourine, Parrot. Копии лежат в `scratchpad/repos/`.

Что о VoicePaste известно мне из репозитория (`projects/voice-paste`: README, docs/map.md, spec/*, TextInserter.swift, WhisperKitTranscriber.swift) [источник]:
- горячая клавиша регистрируется системой (Carbon-подобная регистрация, не перехват потока), обязательно с модификатором, по умолчанию ⌥Space; режимы «переключение» и «удержание»; Esc приостанавливает запись на 4 с, не стирая накопленное;
- вставка: текст кладётся в буфер всегда (инвариант «готовый текст всегда в буфере»), затем одно ⌘V через HID в приложение, бывшее активным в начале записи; ушёл фокус / Finder / Системные настройки — остаётся буфер; прежний буфер не восстанавливается;
- распознавание только WhisperKit, одна модель 626 МБ; `DecodingOptions` без `promptTokens` (словарь действует только после распознавания, как замена); отрезка хвостовых «галлюцинаций» и тишины по RMS, VAD нет;
- нет ИИ-постобработки, нет контекста приложения, нет правки выделенного, нет CLI/URL scheme/MCP, нет автоотправки;
- уникальное: учебный режим (живая расшифровка окнами по 10 с, абзацы по паузам, таймкоды, дозапись лекции), импорт файлов включая OGG/Opus, история с FTS, строгий «в сеть ходит только явная установка модели».
Расхождение: docs/map.md и spec/readiness говорят, что перевод выделенного в учебном режиме идёт системным `Translation`; в коде (`grep -i translat`) использования этого фреймворка я не нашёл [не проверено — возможно, ещё не реализовано].

**Handy.** Самый популярный открытый проект (33,7 тыс. звёзд, MIT). Tauri, Whisper и Parakeet V3, VAD Silero. Горячая клавиша: удержание, тап (защёлка) или оба по порогу. Вставка: Ctrl+V, прямой набор, Shift+Insert, Ctrl+Shift+V или внешний скрипт; автоотправка Enter/Ctrl+Enter/Cmd+Enter; CLI: `handy --toggle-transcription`, `--toggle-post-process`, `--cancel` — отправляются в уже запущенный экземпляр; интеграция Raycast (сторонняя). Из кода: `paste_tx` — вставка с «чтением-квитанцией»: на pasteboard кладётся не текст, а обещание (`declareTypes:owner:`), AppKit вызывает владельца при реальном чтении; прежний буфер восстанавливается, только когда чтения затихли, и только если `changeCount` не изменился (чтобы не затереть новое копирование пользователя); добавлены маркеры скрытого/временного типа для менеджеров буфера [источник: src-tauri/src/paste_tx/mod.rs, macos.rs; тикет #502]. `secure_input.rs` — детект Secure Event Input, при длительной блокировке клавиатурных хоткеев запасная регистрация через Carbon [источник; тикет #1578]. Есть режим перевода китайских скриптов (упрощённый/традиционный) [источник].

**VoiceInk.** Нативный Swift, GPLv3 (код не копируем в MIT-проект). Пишет режимы: приложение/сайт (определение URL браузера, `BrowserURLService`), контекст экрана (ScreenCaptureKit + Vision OCR), буфер, выделенный текст (`SelectedTextKit`); результат — вставка, «ответ» ассистента или выполнение пользовательской команды (`OutputMode: paste / respond / customCommand`) [источник: ModeConfig.swift, TranscriptionDelivery.swift]. После вставки может нажать Enter/Shift+Enter/⌘Enter [источник: FinishAndSendSettings.swift]. Автообучение словаря: после вставки наблюдает поле через Accessibility и сравнивает итоговый текст с вставленным (`AutoLearn*`) [источник]. Вставка: буфер + ⌘V или AppleScript, опциональное восстановление буфера с проверкой владельца сессии, пауза 0,1 с перед ⌘V [источник: CursorPaster.swift]. Облачные провайдеры включают Deepgram, AssemblyAI, ElevenLabs, Soniox, Groq, Mistral, Gemini и др.

**OpenWhispr.** Electron, MIT, самый «широкий» открытый: диктовка, агент с именем (голосовой ассистент отдельным хоткеем: «команда без обработки; выделенный текст правится на месте»), перевод диктовки отдельным хоткеем, встречи с диаризацией и «отпечатками голоса», заметки, импорт YouTube-ссылок, корпоративные политики. Публичный REST API (ключи `owk_live_…` со scope-ами `notes:read/write`, `transcriptions:read`), MCP-сервер `https://mcp.openwhispr.com/mcp` с OAuth или ключом, файл `agent-skills/openwhispr-api/SKILL.md` для агентов [источник]. Нативные помощники: `macos-fast-paste.swift` (⌘V с поиском клавиши по раскладке), `macos-text-monitor.swift`, `macos-globe-listener.swift` [источник: resources/]. Цена: аналитика в клиенте (`analytics.js`), облако с аккаунтом.

**FluidVoice.** Swift, GPLv3, 12 тыс. звёзд (по API). Сильные приёмы вставки: `PasteVerifier` читает сфокусированный элемент до и после вставки через AX и сообщает «не приземлилось» только если значение, число символов и каретка не изменились два чтения подряд; `DeliveryTargetAssessment` отказывается вставлять только при уверенно нередактируемой роли (контейнеры AXGroup/AXWebArea намеренно не считаются нередактируемыми — GPU-терминалы и удалёнка сообщают AXWindow/AXApplication, но принимают ⌘V); `PasteKeyCodeCache` определяет код клавиши V по текущей раскладке и обновляется по уведомлению о смене источника ввода [источник: Sources/Fluid/Services]. Режимы Write (переписать выделенное) и Command (команды Mac).

**TypeWhisper.** GPL-3.0 + коммерческая, 1.7.0 на 14.10.2026. «Workflows» — преобразования с триггерами (приложение, сайт, хоткей, глобально, палитра); цепочка провайдеров LLM (Apple Intelligence на macOS 26+, Groq, OpenAI, локальный MLX и т. д.) с откатом; «Undo Last Dictation» и «Restore Raw Transcript» глобальными хоткеями без записи в буфер; «Dictation Recovery» хранит три последние успешные диктовки 24 часа; сниппеты с `{{DATE}}`, `{{TIME}}`, `{{CLIPBOARD}}`; HTTP API `/v1/*` (в т. ч. `POST /v1/dictation/start|stop`, `GET /v1/history?q=`), CLI, плагины (Obsidian, Linear, MCP Client, Script Runner), импорт словаря из Wispr Flow и Handy, пакеты терминов, SRT/WebVTT [источник: README, docs/release-readiness.md].

**Muesli.** Swift, MIT. Диктовка с Parakeet на Neural Engine (заявлено ~0,13 с задержки — цифра README [не проверено]), «Quill»: выделил текст и сказал инструкцию — правка; без выделения — генерация в позиции курсора. Двойной тап — режим без рук. Встроенный `muesli-cli` для агентов: команды `spec`, `info`, `transcribe`, `meetings list|get`, `dictations list|get`, `meetings update-notes --stdin`, вывод JSON-конвертом; подсказка «что должен делать агент» прямо в README. Пост-хуки: пользовательский исполняемый файл получает JSON на stdin после встречи. Apple Shortcuts/Siri: старт/стоп диктовки, «Get Last Dictation» [источник].

**Hex (Rust).** Новый MIT-проект; старый Swift-репозиторий kitlangton/Hex помечен «legacy» со ссылкой на новый под `anomalyco/hex`. Удержание Option, двойной тап — продолжать, Esc — отмена, ⌥⇧V — вставить последнее. «Voice Action» (⌥⌘): инструкция + выделенный текст + имя приложения + хост Brave уходят в провайдера, результат вставляется. Голосовые команды локально (Moonshine), список фраз по контексту, пользовательские — в `~/.config/hex/hex.config.ts` (TypeScript через Bun); к проекту приложен skill `hex-personal-commands`, который велит агенту править конфиг и прогонять `bun run check` [источник: README, skills/hex-personal-commands/SKILL.md]. Выставляет SDK `@kitlangton/hex` для встраивания локальной расшифровки [источник: ROADMAP.md]. Права: Микрофон, Input Monitoring, Accessibility.

**OpenLess.** AGPL. «Паки стилей» (Raw, Light, Structured, Formal; по умолчанию — Structured, описан как «структурированный промпт для сотрудничества с ИИ-кодером»), маркетплейс паков, подсказки декодеру из словаря (бюджет 240 символов), `DictationContext` — неизменяемый снимок настроек на сессию (приложение, контекст курсора); потоковая вставка символ за символом с авто-определением терминала по bundle id (в терминале перевод строки — LF, в чатах — Shift+Return, чтобы не отправлять) [источник: dictation_context.rs, streaming_insert.rs, style_packs.rs]. Маршрутизация «вопрос/правка/сочинить» для выделенного текста.

**Whispering (epicenter).** AGPL монорепо. Версия приложения в репозитории — «заметки голосом»: записи, расшифровки, преобразования и их результаты — обычные файлы Markdown в папке под Git (`recordings/*.md`, `transcriptions/*.md`, `transformations/*.md`), без базы и аккаунта; агенты читают их напрямую [источник: apps/whispering/README.md]. Диктовка в чужие приложения в этой сборке не входит [источник].

**VoiceTypr.** AGPL, Tauri; CLI `voicetypr transcribe --file … --json`, `record --until-silence --json`, `status`, `models`; «Network Sharing» — одна установка служит сервером расшифровки для других [источник].

**Прочие.** OpenSuperWhisper — MIT, один модификатор / Fn / боковая кнопка мыши как триггер [источник]; Parrot — MIT, `parrot doctor` проверяет права и настройку клавиши fn [источник]; Amical — контекст по активному приложению [источник]; Koe — конфиг и словарь простыми файлами в `~/.koe/`, подсказка «пусть Claude Code сгенерирует словарь» [источник]; Ghost Pepper — локальная очистка Qwen 3.5 0,8B за 1–2 с [источник]; Earheart — Parakeet + Granite 4 Micro, «ничего не отправляет, Enter нажимает человек» [источник]; Buzz и Vibe — расшифровка файлов с экспортом субтитров, реальное время через микрофон [источник]; drewburchfield/macos-mic-keepwarm — документирует, что на Apple Silicon микрофон «засыпает» и первые 2–5 с речи теряются, особенно при Bluetooth; лекарство — держать открытым поток захвата [источник].

## 5. Инструменты и приёмы для работы с ИИ-агентами голосом

1. **Нативный `/voice` Claude Code** (код.claude.com): запись в строку ввода терминала; подсказки словаря из имени проекта и ветки git; hold по повтору клавиши терминала (задержка прогрева) либо tap; аудио уходит в Anthropic, нужен claude.ai-вход [источник]. Следствие: у владельца уже есть бесплатный голосовой ввод в Claude Code, но он не заменяет системную диктовку в чат/почту и не работает без аккаунта/через API-ключ [вывод].
2. **Голосовой диалог с агентом** — VoiceMode (MCP, TTS Kokoro + Whisper локально, tool `converse`, определение тишины, плагин для Claude Code `/voicemode:converse`) [источник]. Для нескольких параллельных сессий — «conch»: очередь/мьютекс на голос, одна сессия говорит, остальные ждут; хэртбит TTL 90 с, чтобы очередь не зависала [источник: voice_mode/tools/conch.py].
3. **Агент спрашивает — отвечаешь голосом**: Superwhisper ставит плагин в конфиг каждого агента (хуки: вопрос, «закончил ход», запрос разрешения; одобрение голосом) [источник]; Spokenly — MCP-инструмент `ask_user_dictation` на локальном HTTP-порту + пользовательское правило «задавай вопросы через этот инструмент» [источник].
4. **Диктовка прямо в терминал/чат агента**: Earheart/Ghost Pepper/OpenLess/VoicePaste — вставка в окно с фокусом; Enter нажимает человек (безопасно) или автоотправка по настройке (Handy, VoiceInk, Claude Code при ≥3 слов) [источник].
5. **«Диктуй → структурированный промпт»**: OpenLess (стиль Structured по умолчанию: пример на странице — сумбурная речь превращается в нумерованный список с ограничениями и тоном) [источник]; Earheart — только очистка от «э-э» и повторов [источник]; Wispr/Typeless/Willow — форматирование списков [маркетинг].
6. **Распознавание терминов кода**: Wispr — «Variable recognition» (camelCase, snake_case, акронимы; в Cursor нужен режим Screen Reader Optimized) и File Tagging [источник]; Claude Code — подсказки по проекту/ветке [источник]; TypeWhisper — пакеты терминов [источник]; Aqua — «понимает синтаксис, библиотеки и фреймворки» [маркетинг].
7. **Выделенный код/контекст как часть промпта**: VoiceInk кладёт в системный промпт блоки `<CURRENTLY_SELECTED_TEXT>`, `<CLIPBOARD_CONTEXT>`, OCR экрана [источник: AIEnhancementService.swift]; Hex Voice Action — выделенный текст + приложение + хост сайта [источник]. Передачи пути файла или скриншота в промпт агента как отдельной возможности у голосовых приложений я не нашёл [не проверено].
8. **Голосовые заметки с последующей обработкой агентом**: Minutes, Muesli CLI и Superwhisper CLI/MCP отдают расшифровки агенту (`search_meetings`, `dictations list`, `search`), агент пишет итоги обратно (`meetings update-notes`) [источник]; Whispering хранит всё Markdown-файлами в Git [источник]; OpenWhispr — REST+MCP+Obsidian-совместимые заметки [источник].
9. **Интеграции Obsidian/Notion/Telegram**: TypeWhisper (плагин Obsidian, Linear, Webhook), MacWhisper (Notion, Obsidian, Zapier, n8n, webhooks), Minutes (Obsidian, Logseq) [источник]. Telegram-интеграции именно как приёмника голосовых — не нашёл у других, VoicePaste импортирует файлы голосовых сам [вывод].
10. **Настройка через агента**: Hex — skill + TS-конфиг; Koe — словарь простым txt; Parrot — словарь файлом; Superwhisper — «Optimizing Superwhisper with AI» в документации [источник].

## 6. Чего нет у VoicePaste и стоило бы (оценка для разработчика, работающего с агентами и пишущего людям по-русски и по-английски)

Ценность: В — высокая, С — средняя, Н — низкая для этого владельца [вывод]. Стоимость: м — малая (дни), с — средняя, б — большая.

| № | Возможность | Откуда | Ценность | Стоимость | Комментарий |
|---|---|---|---|---|---|
| 1 | Восстановление прежнего буфера после **успешной** вставки + метки временного типа + хоткей «вставить последнее» | Handy, VoiceInk, Hex | В | м | Сейчас каждая диктовка затирает буфер и попадает в менеджеры буфера (Maccy и т. п.). Инвариант «текст всегда в буфере» нужен на случай ухода фокуса — оставить его только для исхода `.copied`, а при `.inserted` восстанавливать и отдавать текст через «вставить последнее». Требует защиты `changeCount` (Handy) [вывод]. |
| 2 | CLI/URL scheme: `voicepaste toggle`, `voicepaste transcribe file.ogg --json`, `voicepaste last` | Handy, Muesli, TypeWhisper, voicetypr, Superwhisper | В | м–с | Даёт Raycast/Hammerspoon/Stream Deck/хуки агентов. `transcribe` по голосовым Telegram — то, чего у других нет (OGG). Уже есть очередь импорта и движок [вывод]. |
| 3 | Гибрид «удержание или тап-защёлка» (+ double-tap) | Handy, Muesli, Hex, VoiceInk, TypeWhisper | В | м | Автомат диктовки уже чистая функция; нужен порог удержания (у Handy `hold_threshold_ms`). Для длинных промптов не держать клавишу [вывод]. |
| 4 | Подсказка декодеру словарём и контекстом (`promptTokens` WhisperKit: словарь пользователя, имя проекта/папки из заголовка окна терминала/IDE, ветка) | Claude Code `/voice`, OpenLess, Wispr | В | м–с | Сейчас словарь только «заменяет после». Для имён файлов и терминов смещение декодера работает лучше замены. Эффективность на русском+английском миксе не измерена [не проверено; в коде `DecodingOptions` без `promptTokens` — источник]. |

Whisper-задача `translate` на выбранной модели, скорее всего, плоха [вывод, не проверено]. |
| 7 | Второй движок Parakeet TDT v3 (FluidAudio, CoreML/ANE) как опция | VoiceInk, Handy, Muesli, OpenSuperWhisper, Ghost Pepper, FluidVoice | В | с | Заявленная задержка ≈0,13 с у Muesli (README) против текущей модели 626 МБ; список языков v3 включает 25 европейских — русский в ней есть по моим сведениям [не проверено по источнику]. Нарушает инвариант «ровно одна модель» — нужно менять спецификацию. |
| 8 | Необязательная локальная LLM-очистка: слова-паразиты, самоисправления, пунктуация; Apple Intelligence (macOS 26+) или MLX 0,8–2B | Ghost Pepper, Earheart, Muesli, TypeWhisper, FluidVoice | В | б | Самый заметный разрыв по качеству текста. Конфликт с обещанием «без сервера» снимается локальностью; цена — загрузка модели, задержка 1–2 с (0,8B у Ghost Pepper) и тесты на русском [не проверено]. |
| 9 | Режимы по приложению (bundle id/URL): язык, автоотправка, стиль («промпт для агента», «сообщение», «код/термины») | VoiceInk, TypeWhisper, Superwhisper, Hex | В (после №8); С без LLM | с | Без LLM уже полезно: язык и автоотправка на приложение (терминал — выкл.) [вывод]. |

## 7. Что у VoicePaste на уровне или лучше

- **Лекции:** живая расшифровка окнами, абзацы по паузам говорящего без LLM, таймкоды, дозапись лекции. У открытых проектов такого не нашёл; ближайшее — записи встреч с диаризацией и сводками (OpenWhispr, Muesli, TypeWhisper, Superwhisper) и файловые транскрибаторы с таймкодами/субтитрами (Buzz, Vibe, MacWhisper) [вывод; отсутствие совпадений — не доказательство отсутствия, у коммерческих продуктов страницы читал лишь верхнего уровня].
- **Голосовые Telegram (OGG/Opus)** — явное требование спецификации; в README Muesli перечислены mp3/mp4/m4a/wav, у остальных OGG не заявлен [источник + вывод].
- **Строгая приватность:** сеть только по явной загрузке модели; у OpenWhispr есть клиентская аналитика (`analytics.js`) [источник], у VoiceTypr настройки аналитики [источник]. Claude Code /voice и коммерческие (Wispr, Aqua, Typeless) — облачные [источник].
- **Надёжность хоткея:** системная регистрация без перехвата потока — не нужен Input Monitoring (его требует Hex) и нет класса отказов Secure Event Input, от которого Handy городит запасной путь [источник + вывод].
- **Безопасность вставки:** снимок цели в начале записи, вставка только если цель всё ещё впереди, иначе текст остаётся в буфере; такого же уровня в README других проектов не заявлено (у FluidVoice — похоже, `targetRestoreFailed`) [источник].
- **Прерывание:** Esc приостанавливает на 4 с без потери накопленного — у TypeWhisper двойное Esc отменяет с настройками [источник]; у VoicePaste сильнее в части «не потерять» [вывод].
- **Строгая спецификация и тесты** (132 блока, 235 кейсов) — выше, чем у любого просмотренного проекта по документированию инвариантов [вывод].

## 9. Что не подтверждено и чего не хватило

- Первичных документов нет для: режимы hold/hands-free и «Context Awareness» у Wispr Flow; хоткеи и URL scheme у Superwhisper (нашёл CLI и MCP, не «deep links»); MCP/CLI у Aqua; внутренний Cursor Voice Mode; Codex CLI voice; Talon (только лендинг); детали встроенной диктовки macOS 27 (в TechCrunch только iOS 27).
- Цифры точности/скорости (Avalon 97,4 %, Muesli 0,13 с, Willow 200 мс, Ghost Pepper 1–2 с) — заявления вендоров, не измерялись. Замеров на русском нет ни у кого; для владельца нужен собственный тест (в Китае через VPN — только на сервере/локально по CLAUDE.md).
- Не читал код: OpenWhispr (кроме списка файлов и двух помощников), Muesli, Hex-Swift, Amical, Tambourine, voicetypr — по ним только README. Не разбирал мелкие клоны (десятки), Windows/Linux-ветки.
- Звёзды у FluidVoice (12 тыс.) и Handy (33 тыс.) — по API на 14.10.2026; в рост может входить накрутка, не проверял. VoiceStudio (64 тыс.) исключён.
- Для самого VoicePaste читал не весь код: поведение при Bluetooth, звуки, пауза медиа определил по `grep` по именам API — отсутствие совпадений ≠ точное отсутствие функции.
- Релевантность локальной LLM-очистки на русском, Parakeet v3 на русском, системного `Translation` для технических терминов — не проверялись; нужен малый замер на 20–30 фразах владельца до решения.
